# Ordered WebGL rasterizer prototype

This is an asset-free verification harness for an experimental WebGL2 GS
rasterizer. It is **not connected to the game renderer** and does not establish
that SSX 3 is playable or meets its frame-time target on this backend.

The fragment shader processes each tile's primitives in submission order. Each
fragment keeps its current color and integer depth locally, including alpha-test
failures that write color without writing depth. The batch needs one raster draw
instead of a destination snapshot and separate passes for every primitive.

The software reference uses the repository's unchanged `gs.cpp` and `raster.cpp`.
All geometry, textures and palettes are generated by the fixture. No ROM, BIOS,
guest executable, save, captured game memory or generated guest code is needed.

## Build and run

Use Emscripten **6.0.11** and Node.js with **puppeteer-core 25.16.0**. The build
script accepts `EMXX` when `em++` is not on PATH:

```sh
scripts/build_webgl_ordered.sh
python3 -m http.server 8262 --bind 127.0.0.1 --directory build/webgl-ordered
```

Open `http://127.0.0.1:8262/` to run the positive matrix. In another terminal,
run both browser drivers:

```sh
# Keep browser tools outside the source checkout if they are not already installed.
npm install --prefix /tmp/ssx3-browser-tools --no-save puppeteer-core@25.16.0
NODE_PATH=/tmp/ssx3-browser-tools/node_modules node scripts/test_webgl_ordered.cjs chromium
NODE_PATH=/tmp/ssx3-browser-tools/node_modules node scripts/test_webgl_ordered.cjs firefox
```

The driver uses `/usr/bin/chromium` and `/usr/bin/firefox` by default. Override
`SSX3_CHROMIUM_BIN` or `SSX3_FIREFOX_BIN` for other installations. Other options:

- `SSX3_WEBGL_ORIGIN`: verification page URL; default `http://127.0.0.1:8262/`.
- `SSX3_WEBGL_ARTIFACT_DIR`: destination for evidence JSON; default a fresh temporary directory.
- `SSX3_WEBGL_HEADLESS=1`: opt into headless functional testing. A software WebGL
  result is useful for correctness but does not qualify hardware performance.

No WebGPU, Vulkan, GPU override flags, cross-origin isolation or game assets are
used by this harness. WebGL2 is required.

## What the checks prove

Each browser runs **1,504 bridge cases**, comparing all 4,096 color pixels and
all 4,096 integer depth values. The matrix includes 1,490 software-reference
cases and independent expected images for a constant-color/depth horizontal line,
constant-alpha identity blending, constant STQ nearest sampling, the Q=1
minification/magnification filter boundary and constant fog. The constant-attribute
oracles also check CPU output; the software adapter models the filter-boundary
case with matching base-level linear filtering, rather than implementing mip LOD.
The raw shader route runs 1,536 cases, retaining 32 additional full-depth-domain cases. The matrix covers:

- Line coverage: endpoint exclusion, reversal, clipping, fractional/zero-length
  lines, fixed-point rounding, and interpolated color/depth/texture/fog.
- Sprites: fractional/reversed rectangles, clipping and empty coverage, separate
  X/Y texture interpolation, final-endpoint attributes, Q zero/sign changes,
  direct/indexed sources, nearest/bilinear sampling, texture functions and fog.
- 81 blend equations and factors, alpha comparisons, and all four failure modes.
- Overlapping triangles, depth comparisons and masks, destination alpha, PABE,
  FBA, partial framebuffer masks, clamp/wrap and scanline masks.
- 32-, 24- and 16-bit color/depth representations, including alternate 16-bit layouts.
- Direct and indexed textures: PSMCT32/24/16, PSMT8/4/8H, 16-bit palettes and TEXA.
- Nearest/bilinear sampling, four coordinate clamp modes, four texture functions,
  texture alpha, fog and controlled texture coordinate interpolation.
- A filtered, overlapping cutout case using `TEST=0x515cd`, plus seeded overlapping scenes.
- All 16 complete-channel framebuffer masks with depth writes on/off, FBA on/off,
  flat/Gouraud colors and untextured/nearest/bilinear inputs (384 cases). Four
  partial-bit and nine packed-format cases require the ordered route instead.

Nonzero complete-channel masks retain the ordered route. A private hardware-mask
prototype passed this matrix and independent retry checks, but its final-source
timing did not show a meaningful Firefox gain; it remains unselected. Zero-mask
cases exercise the existing hardware route. The routing assertions prevent an
accidental all-fallback pass for eligible unmasked triangles.

Five negative controls must fail the pixel comparison: suppressed depth writes,
reversed primitive order and restoring weighted interpolation of equal color,
texture or fog attributes. They must fail through incorrect color/depth values,
with no graphics API error. The driver records these as expected detections.

Power-of-two fixture areas avoid unrelated floating-point quantization artifacts
in the existing CPU triangle reference. These controlled cases do not replace
captured-game comparisons with arbitrary geometry. The optional timer query
measures one 64×64, twelve-triangle GPU batch only; it excludes setup and is not
an FPS measurement.

## Independent fixed-point coverage

`node scripts/test_webgl_coverage.cjs chromium` (or `firefox`) uses the same origin
and artifact-directory variables as the main driver. Its 2,664 cases compare
66,600 sampled pixels with an independent integer GS12.4 coverage oracle at
64×64, 512×448, 640×448 and 511×447. Both ordered and hardware routes are exercised
with small triangles, reversed winding, large offscreen edges through pixel
centers, and valid full-coordinate skinny triangles whose exact determinant is
two. Coverage is checked with constant colors and depth disabled; these patches
do not qualify general interpolation, full-game fidelity or performance.

Two restoration controls must fail without API errors: the preceding floating
edge calculation and hardware triangle coverage. The corrected shader uses exact
integer determinants, with a guarded signed-32-bit path and wide products when
needed. The hardware route covers a clipped bounding rectangle and applies GS
edges in the fragment shader, preventing hardware edge quantization from dropping
GS-covered pixels. This can increase vertex and fragment work; it is not a speed
optimization. `tests/raster_coverage.cpp` separately verifies 36 valid GS-coordinate
cases and 900 sampled pixels in the software rasterizer, including both windings,
mirroring, offscreen geometry and three framebuffer sizes.

## Data layout and remaining work

Each primitive occupies three 32-byte vertices (lines and sprites store A, B, B): `float x, y; uint32 z, rgba; float s, t,
q; uint32 fog`. Vertex data is uploaded to RGBA32UI, two texels per vertex.
Eight-pixel tile headers contain the ordered list offset and count. Color and
depth inputs are RGBA8UI and R32UI; separate integer attachments receive outputs.
The test texture adapters also exercise normalized RGBA/R8 and RGB5_A1 inputs.

The uniform block contains eight `uvec4` values. Its word layout is:

| Words | Values |
| --- | --- |
| 0–3 | PRIM, TEST, ALPHA low word, ALPHA high word/FIX |
| 4–7 | FBMSK, PABE, FBA, COLCLAMP |
| 8–10 | Initial color, initial depth, SCANMSK |
| 11–13 | Packed scissor X, packed scissor Y, ZMSK |
| 14–16 | TFX/TCC, bilinear flag, WMS/WMT |
| 17–21 | MINU, MAXU, MINV, MAXV, FOGCOL |
| 22–24 | Texture width, height, maximum depth value |
| 25 | Source adapter: integer RGBA, normalized RGBA, indexed8, indexed4, alpha-indexed8 |
| 26–27 | Framebuffer PSM, depth PSM low format bits |
| 28 | Packed TEXA (TA0, TA1, AEM) |
| 29 | Source/palette expansion format in bits 0–1; bit 2 selects proved pixel-local feedback |
| 30–31 | Opt-in TEX1 low flags and high/K word; see the mip fixture |

Integration still needs real GS command batching, texture and palette lifetimes,
physical VRAM alias coherence, presentation and context-loss recovery. The
GPU bridge below supplies transfers and owned-resource cleanup, but still needs
those renderer-level integrations. The fixture does not implement points,
dithering, mip LOD or general framebuffer feedback. Region coordinates
in these tests stay within the supplied texture storage. Full-game fidelity,
sustained performance, audio, saves, controls and physical phone testing remain
separate release requirements.

The native bridge additionally supports a guarded framebuffer-source subset:
nearest-filtered UV sprites mapping one destination pixel to one source texel
center. Both logical and physical source bounds are checked after clipping.
Region clamp/repeat, scaling, STQ and other unsupported mappings retain the
native fallback. For self-feedback, every source coordinate must identify the
same destination pixel. The host proves both incoming and queued sprites before
suppressing native feedback flushes, and proves the complete batch again before
submission. Word 29 bit 2 tells the kernel to decode its current local pixel;
the bridge binds a dummy source texture to avoid a graphics API feedback loop.
Overlapping sprites observe preceding color and alpha changes in submission
order. General cross-pixel framebuffer feedback still requires native snapshots.

`framebuffer.cpp` in the native backend fixture checks 46 complete 64×64 images,
14 unsafe-route rejections and incoming/queued identity guards. It includes
GPU-owned source pixels that differ from GS RAM, palette-alpha decoding,
flips/clipping, sequential overlapping feedback, blending and preserved alpha.
Controls using stale initial pixels or the wrong index channel must fail the
pixel comparison without API errors. Run it through `test_webgl_backend.cjs`.

## Runtime state adapter

`runtime/src/gs/webgl/register_stream.hpp` converts the runtime's borrowed
`State` and completed `Vertex` packets into GS register writes through a caller
supplied `(uint8_t register_id, uint64_t value)` sink. It resolves PRMODE,
normalizes strips/fans into independent primitives, and caches unchanged setup
registers using the caller's setup revision. Pass a new revision whenever a
non-vertex GS register changes; the live runtime's `g_setup_generation` supplies
that contract. Vertex attributes are checked on every draw.

Repeated XYZ2 kicks, TRXDIR transfers, CLUT loads and TEXFLUSH writes remain
actions even when their values match. Setup replay masks TEX0's CLD field so it
cannot duplicate an explicit palette load. TEX2 is already resolved into the
runtime context's TEX0. Call `invalidate()` after backend reset or register
mutations outside this adapter. The sink owns its queue and must copy writes
before returning; state and vertices are not retained. If a sink throws after
partially accepting commands, recover/reset the backend and invalidate the
adapter before resuming.

The asset-free `webgl-register-stream` CTest target checks register packing,
context/mode selection, revision caching, repeated actions and invalidation.
CI also compiles and runs the same test under Emscripten/Node. This adapter is
an integration boundary, not a complete backend: it does not own VRAM, transfer
payloads, readback, presentation, save state or context recovery. The shipping
game still does not select this WebGL renderer.

The separate `gs-readback` CTest target exercises the current runtime's RGB24
and Z24 local-to-host transfers. Its 162 cases compare bulk reads with quadword
chunks, check output guards and completion padding, and restore a snapshot with
pending final-pixel bytes. CI also runs this fixture in Wasm/Node. These transfer
checks do not establish GPU cache coherence or full-backend save correctness.

## GPU bridge validation

`runtime/src/gs/webgl/ordered_raster.js` is a synchronous GPU-only bridge around
this kernel. It receives host-owned normalized RGBA8 color and D32F depth views,
converts the affected region into integer attachments, processes the ordered
batch, and resolves color/depth back to the host. It preserves external object
ownership and exposes `destroy()` for its own resources. The host must restore
its GL state, check errors at frame boundaries, and split batches at hazards.
The bridge caches programs, uniforms, and framebuffer attachments and uploads
only populated vertex/list rows and the affected tile rectangle. Tile lists use
reusable typed arrays with count/prefix/scatter passes; submission order is
preserved without per-tile Maps or Arrays. Target-size cache entries retain their
own tile counts, and destruction releases scratch buffers.

Run the bridge matrix with:

```sh
NODE_PATH=/tmp/ssx3-browser-tools/node_modules node scripts/test_webgl_ordered.cjs chromium bridge
NODE_PATH=/tmp/ssx3-browser-tools/node_modules node scripts/test_webgl_ordered.cjs firefox bridge
```

This mode exercises **1,504 cases per browser**, comparing the actual resolved
color and depth with the CPU renderer and the independent constant-line image.
It also checks five shader negative controls and 20 allocation/retry cases.
The bridge accepts the supported 32/24/16-bit color views and a 24-bit-or-smaller
depth domain; D32F cannot reconstruct all 32-bit integer depth values. The raw integer kernel
matrix retains its 1,536-case coverage. Unsupported bridge cases are explicitly
listed as skipped, rather than counted as passes. No tests are removed from the
raw kernel matrix.

The bridge never reads pixels back to the CPU. The fixture performs extra
snapshots and readbacks to verify the resolved target, including maximum Z24.
Its counters describe bridge operations only. Real renderer integration,
resource/VRAM coherency and full-game performance remain unqualified.

Bridge checks also exercise target-size cache eviction, restoration of a previous
size, idempotent destruction, and preservation of the host's framebuffer,
texture, and depth renderbuffer. The cache retains at most four target sizes.
The expanded GS16 framebuffer source adapter distinguishes a normalized RGBA8
view containing already-expanded 5-bit color and a raw alpha high bit from an
RGB5_A1 texture. Reapplying RGB5_A1 normalization to the former would lose color
precision and interpret its alpha incorrectly.

Line positions must stay within the GS 12.4 coordinate domain (±4096 screen
pixels). Integer rational coverage prevents GPU reciprocal approximations from
moving exact half-pixel ties. Coverage-only cases use zero attributes to isolate
them from weighted-sum rounding in the unchanged CPU line reference; interpolated
attribute cases use power-of-two lengths. The independent horizontal-line image
checks that the last vertex's flat color and constant depth survive a
non-power-of-two length. Arbitrary line attributes still need broader fidelity
checks. Bridge counters distinguish lines, sprites, triangles, and total primitives.

Sprites carry two original GS endpoints rather than triangle-expanded attributes.
The final endpoint supplies flat color, depth, Q and fog regardless of IIP.
S and T interpolate independently along X and Y before division by the final Q
(or Q=1 when zero); FST uses fixed UV coordinates instead. A host adapter must
preserve those inputs before any legacy perspective division or tessellation.

The resolved-target check uses its own conversion shader and verifies raw color
bytes without applying framebuffer-format quantization. That prevents the
verification step from hiding incorrect low color bits. The bridge skips its
depth copy/sample when ZTE is disabled, or when ZTST is ALWAYS and ZMSK prevents
writes, and disables depth writes during resolve for those batches. Its depth
blit/bypass counters exclude verification-only copies.

Dedicated identity-blend cases cover ALPHA selecting the same A and B with D
selecting the source: `(A-A)*C+Cs` equals Cs. The cases cover all valid equal
selectors, both PABE states, partial masks and 16-bit color. Each bridge case
also verifies that the host GS packet was not mutated. These checks support
future optimizations; the current bridge retains the general blend calculation.

## Hardware opaque triangles

Eligible batches use a hardware triangle draw directly into the host RGBA8/D32F
framebuffer. The vertex shader shifts GS coordinates by half a pixel; the fragment
shader shares the ordered path's coverage, integer depth, texture, fog and color
functions. It does not use interpolated hardware depth. Fixed-function depth
comparison/writes preserve Z24 order without input copies, tile lists or resolve.

Eligibility is deliberately explicit: triangles/strips/fans, PSMCT32/16/16S, full
color writes, Z24 with the full 24-bit domain, no destination-alpha test, and
blending disabled or an exact source-color identity. Alpha testing must be
disabled, ALWAYS, or FBONLY with depth writes prevented by ZMSK or disabled ZTE.
Source/palette feedback is excluded. Other batches retain ordered rendering.
FBA, scanline masks, scissoring and depth masks remain active.

The matrix includes 108 additional cases that require hardware routing in bridge
mode: winding, fractional coordinates, viewport clipping, scissoring, direct and
indexed textures, filtering, clamp modes, texture functions, FBA/PABE, fog and
depth modes. Wide-u32 depth inputs also test saturation before conversion;
rounding a full-range delta to 2^32 must not wrap the interpolated depth.
Both raster paths share this corrected saturation.

The fixture allocates its snapshot resources after a hardware draw because that
path does not allocate intermediate integer targets. Counters distinguish
`opaqueBatches`/`opaqueTriangles`; depth copy/bypass counters describe ordered
batches only. This path still requires captured-game, sustained performance,
context recovery and full-game qualification before release.

Logical 16-bit hardware outputs use the same pack/expand operations as the
ordered renderer. Their host RGBA8 target view must contain expanded GS16 values
(RGB five bits shifted left three; alpha 0 or 128), including untouched pixels.
Hosts must normalize other storage representations before exposing that view.
The current captured shadow targets are cleared before drawing.

An additional 123 cases prove masked-depth FBONLY equivalence across all alpha
comparisons, PABE/FBA and PSMCT32/16/16S, including disabled ZTE. Explicit guards
require the ordered path for depth-writing FBONLY and other nontrivial failure
modes. Depth comparisons remain active where required. A separate hardware
shader omits depth entirely only with disabled ZTE or ALWAYS plus masked writes.
It also skips coordinate normalization for flat, untextured, unfogged draws whose
attributes need no interpolation. `depthFreeOpaqueBatches` counts that subset;
tests require both depth-free and depth-tested hardware programs to run.

## Slanted flat-attribute coverage

A further 32 cases use slanted, thin, fractional, clipped, reversed and degenerate
triangles with constant nonzero color/depth. They avoid assuming power-of-two
barycentric weights and exercise the ordered path. The CPU software model now
selects flat colors directly and preserves equal depths, with independent native
and Wasm constant-value regressions. The browser compares full targets against
that model; no tolerance was added. Both depth/order fault controls remain active.

## Data texture allocation recovery

Bridge verification also runs `allocation.html`, with twenty first-allocation
and growth faults across R32UI and RGBA32UI data textures. Null texture handles with or without a pending GL error,
storage/parameter exceptions and an actual invalid-storage GL call must report
failure, preserve the previous cached handle/dimensions/pixels, release temporary
resources, and allow an exact clean retry. Successful growth retires the previous
texture. The preceding implementation fails these checks. Expected driver
warnings from the deliberately invalid calls remain in the browser evidence;
uncaught application errors still fail verification. These checks qualify helper
allocation recovery, not recovery of an entire game from context loss.

## Texture lookup precision

Normalized color, palette, mip, framebuffer-copy and presenter samplers explicitly
use `highp`. GLSL ES 3.00 defaults `sampler2D` to `lowp`; declaring `highp float`
does not change sampler precision, which determines lookup-result precision.
These shaders reconstruct GS color bytes and palette indices from normalized
samples, so their sampler precision must be explicit. See the
[GLSL ES 3.00 specification](https://registry.khronos.org/OpenGL/specs/es/3.0/GLSL_ES_Specification_3.00.pdf),
sections 4.5.2–4.5.3 and the chapter 8 introduction. The pinned upstream patch also updates generated
fragment shaders, including the framebuffer-copy programs.

Fresh checksum-verified upstream preparation/build and headed Chromium/Firefox
checks pass: 1,094 exact color/depth cases per browser, both depth/order negative
controls, twenty allocation failure/retry cases, 3,360 mip bridge cases, 13,680
standalone sampler cases, the upstream GS backend matrix and presenter lifecycle,
CPU upload, state restoration and viewport checks. This precision correction
is not established as the cause or resolution of intermittent captured-game
image differences. Subsequent private captured-game runs applying the same
precision declarations each retained one mismatch among 599 shared images in
Chromium and Firefox. The Chromium difference affected twelve RGB pixels with
a maximum component difference of 132; its matching reference image was
independently retained. This change does not resolve those failures or qualify
WebGL performance/audio, and does not change the selected WebGPU release.

## Render-target allocation recovery

After building and serving this fixture, run:

```sh
node scripts/test_webgl_target_allocation.cjs chromium
node scripts/test_webgl_target_allocation.cjs firefox
```

Use the same `PUPPETEER_MODULE`, `SSX3_WEBGL_ORIGIN` and
`SSX3_WEBGL_ARTIFACT_DIR` overrides as the other drivers. The fixture tests 39
failures across first allocation, resizing, and a full four-entry cache. It
injects null texture/framebuffer handles at every allocation point, attachment
exceptions, and an incomplete framebuffer. Every failed replacement must leave
all prior target fields, cache order, complete color images and resource ownership
intact. A retry at the old size must use its original resources; a clean retry at
the new size must complete and evict only the oldest entry when necessary.
These are controlled helper-level failures, not whole-game out-of-memory or
context-loss recovery certification.
